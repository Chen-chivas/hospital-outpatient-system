# 医院门诊管理系统——用户管理与数据统计分析模块  
**需求分析说明书（改进版 / 面向整体项目）**

> 本文档用于改进与补全 `第四组-2013112463-王颖-需求分析.docx` 中“用户管理、数据统计与分析”模块的需求内容，使其在整体项目视角下更加**专业、可实现、可测试、可对接**。  
> 适用对象：项目经理、后端/前端/客户端开发、测试、运维与验收人员。

---

## 1. 文档信息

### 1.1 背景与目标

医院门诊管理系统包含完整业务闭环：**挂号 → 就诊（病历/处方）→ 收费/退费 → 药房发药**，并需要在此基础上提供**多角色权限控制**与**经营/运营数据统计分析**。

本模块目标：

1. 提供统一的“身份与权限体系”（账号、角色、权限点、审计日志），支撑其它业务模块安全运行；
2. 提供全系统数据的统计分析能力（趋势/对比/排行/占比/看板/导出），服务管理决策与运营监控；
3. 为与外部系统（HIS/LIS/PACS/医保等）对接预留身份映射与数据接口扩展点。

### 1.2 模块范围（Scope）

本模块包含两大子模块：

- **UM（User Management）用户与权限管理**
  - 用户、角色、权限点、账号状态、登录鉴权、审计日志
- **SA（Statistics & Analytics）统计与分析**
  - 指标统计、维度分析、趋势对比、看板、报表导出、查询筛选

不包含（明确边界，避免范围蔓延）：

- 不负责实现挂号/就诊/收费/药房的业务细节（但要求提供数据口径与接口）
- 不负责实现外部 HIS/LIS/PACS/医保系统本体，仅做对接适配与数据同步约束
- 不负责“AI 模型训练/管理”，只负责统计与展示；AI 辅助诊断属于就诊模块

### 1.3 术语与缩写（补充）

- **RBAC**：Role-Based Access Control，基于角色的访问控制
- **权限点**：可授权的最小操作单元，如 `REG_ORDER_REFUND`（退号退费）
- **数据口径**：指标定义、统计周期、过滤规则与计算公式的统一规范
- **幂等**：重复提交同一请求，不应导致重复扣减/重复生成记录
- **审计日志**：记录关键操作的人员、时间、对象、前后值（用于追溯）

## 2. 整体系统上下文（从项目角度补全）

### 2.1 角色与用户类型（User Classes）

系统涉及典型角色：

- **管理员**：用户/角色/权限维护、数据字典维护、系统参数配置、审计查看
- **医生**：接诊、病历、处方、查看个人工作量/统计
- **护士**：辅助接诊、患者信息查询、流程协同
- **收费员**：费用核对、收费/退费、票据打印、对账查询
- **药师**：处方审核、调配、发药、库存管理
- **患者（可选）**：线上挂号、订单查询、退号申请（如实现患者端）

> 注：即便当前交付是院内端（医生/护士/收费员/药师/管理员），也建议保留患者账号类型，以兼容线上挂号需求。

### 2.2 模块依赖与数据来源

统计分析的数据来源覆盖全系统：

- 挂号模块：号源、排班、挂号订单、退号/改签、停诊、爽约/黑名单
- 就诊模块：接诊记录、诊断、处方、检查检验申请（如有）
- 收费模块：费用明细、支付流水、退费记录、医保结算记录（如有）
- 药房模块：处方审核/发药记录、库存变动、效期预警
- 用户模块：账号、角色、权限、科室/人员信息（用于维度分析）

### 2.3 关键业务链路（对统计与权限的影响）

1. **挂号支付链路**：支付/退费要求幂等与审计；统计口径必须以“支付状态最终一致”为准  
2. **就诊与处方链路**：处方状态与发药状态影响“处方量、发药量、药品消耗”统计  
3. **权限链路**：不同角色看到的数据范围不同（科室级/个人级/全院级），必须从需求阶段确定数据权限模型（见 4.3）

## 3. 用户与权限管理（UM）需求（改进与补全）

### 3.1 功能清单（UM-FR）

#### UM-FR-01 账号体系

- 支持账号类型：管理员/医生/护士/收费员/药师/患者（可配置启用）
- 账号状态：正常、禁用、锁定（输错密码次数触发）、黑名单（与挂号爽约策略联动）
- 支持账号信息维护：新增、编辑、禁用/启用、重置密码、离职/停用归档

#### UM-FR-02 登录与鉴权

- 登录方式：用户名+密码（课程项目最低要求），可扩展工号/手机号+验证码
- 登录成功后获得会话凭证（Token/Session），所有接口需鉴权
- 支持登出、会话过期、单点登录（可选）

#### UM-FR-03 角色与权限（RBAC）

- 支持角色管理：创建/编辑/禁用角色
- 支持权限点管理：权限点编码、名称、所属模块、风险等级
- 支持给角色授权权限点；给用户分配角色（支持多角色）
- 支持“权限校验”到按钮级/接口级（至少接口级）

#### UM-FR-04 数据权限（Data Scope）

除功能权限外，必须定义数据范围（决定能看到哪些数据）：

- 全院级：可查看全院统计（管理员、院级管理者）
- 科室级：仅查看所在科室（科室主任、护士长等，可选）
- 个人级：仅查看本人业务数据（医生/收费员/药师个人工作量）

#### UM-FR-05 审计日志与追溯

- 对关键操作自动记录审计日志：登录/登出、用户/角色/权限变更、退号/退费、发药、打印、导出等
- 审计日志字段建议：操作者、时间、IP/设备标识、操作类型、对象类型/ID、前后值摘要、结果（成功/失败原因）
- 日志不可篡改：至少做到“只追加写+禁止普通账号删除”；管理员删除需二次确认并留痕（如允许）

### 3.2 典型用例（UM-UC）

#### UM-UC-01 管理员创建收费员账号

- 前置条件：管理员已登录且拥有 `UM_USER_CREATE`
- 主流程：填写信息→分配角色→保存→自动生成初始密码→强制首次登录改密
- 异常：用户名重复；手机号/身份证格式非法；未分配角色；保存失败回滚
- 后置条件：账号可登录；审计日志记录“创建用户”

#### UM-UC-02 用户修改密码

- 前置条件：已登录
- 规则：新密码复杂度要求；禁止与最近 N 次重复；修改后旧会话失效（可选）

### 3.3 权限点建议（示例）

为便于实现与验收，建议以“模块-资源-动作”命名：

- 用户：`UM_USER_READ/CREATE/UPDATE/DISABLE/RESET_PASSWORD`
- 角色：`UM_ROLE_READ/CREATE/UPDATE/DISABLE/GRANT`
- 挂号：`REG_ORDER_READ/CREATE/REFUND/RESCHEDULE`
- 就诊：`VISIT_EMR_READ/WRITE`
- 收费：`BILLING_PAY/REFUND/INVOICE_PRINT`
- 药房：`PHARM_DISPENSE/INVENTORY_ADJUST`
- 统计：`STAT_READ/EXPORT/DASHBOARD_ADMIN`

> 注意：权限点的粒度要能覆盖“导出”和“查看敏感字段”这类高风险操作。

### 3.4 安全与合规要求（UM-NFR）

结合原文档“加密存储、脱敏显示、操作留痕”等要求，补充为可实现条款：

- **密码策略**：长度≥8（可配置），必须包含字母+数字；输错≥5次锁定 15 分钟
- **敏感信息**：身份证/手机号/医保号等入库加密；界面默认脱敏（如 `138****1234`）
- **权限最小化**：默认无权限；授予必须显式；禁用账号立即失效
- **攻击防护（若有 Web/接口）**：防 SQL 注入、XSS、CSRF（按技术栈取舍）
- **导出控制**：导出必须鉴权；默认限制时间跨度与数据量；导出行为写审计日志

## 4. 数据统计与分析（SA）需求（改进与补全）

### 4.1 统计对象与指标口径（核心补全）

原文档给出了“计数/求和/均值/占比 + 维度/趋势/对比/排行”等方法，但缺少**指标定义**与**口径规则**。建议明确以下指标（示例，后续可裁剪）：

#### 4.1.1 核心指标（KPI）

| 指标 | 定义（口径） | 统计周期 | 数据来源 |
|---|---|---|---|
| 门诊量（Visits） | 当日完成接诊的就诊记录数（以就诊模块“接诊完成”为准） | 日/周/月/年 | 就诊 |
| 挂号数（Registrations） | 成功挂号且支付成功的订单数（以挂号模块“已预约/已支付”为准） | 日/周/月/年 | 挂号+收费 |
| 缴费人次（Payments） | 支付成功的缴费记录数（含挂号费、诊疗费、药费） | 日/周/月/年 | 收费 |
| 总收入（Revenue） | 支付成功金额 - 退费成功金额 | 日/周/月/年 | 收费 |
| 处方数（Prescriptions） | 已生效处方数量（以就诊模块处方状态为准） | 日/周/月/年 | 就诊 |

> 关键：每个指标必须指定“状态口径”，避免出现“挂号数到底算下单还是支付”的争议。

#### 4.1.2 维度（Dimensions）

- 时间：小时/日/周/月/季度/年
- 科室：科室ID/名称
- 医生：医生ID/姓名（并受数据权限控制）
- 患者：年龄段、性别、患者类型（医保/自费/商保）
- 费用：费用项目（挂号/检查/治疗/药品）、支付方式（现金/扫码/医保等）
- 渠道：窗口/自助机/线上（来自挂号模块）

### 4.2 统计查询与筛选（SA-FR）

#### SA-FR-01 统一筛选条件

- 时间范围：必填；默认最近 7 天；最大跨度（如 1 年）可配置
- 科室：可多选；默认“我的科室/全部（按权限）”
- 医生：可选；默认“全部（按权限）”
- 渠道：可选
- 患者特征：可选（年龄段、性别、医保类型）

#### SA-FR-02 展示方式

原文档已有图表类型，建议落地到具体页面输出：

- 趋势：折线图（按日/周/月聚合）
- 对比：柱状图/条形图（科室/医生 TOPN）
- 占比：饼图/环形图（费用结构、患者类型）
- 高峰：热力图（小时×科室 或 小时×日期）
- 看板：数字卡片（今日门诊量、今日收入、同比/环比）

#### SA-FR-03 报表导出

导出格式：Excel（.xlsx）/ PDF（由 UI 或服务端生成）。

导出要求：

- 导出内容必须与当前筛选条件一致，并记录“导出时间、导出人、筛选条件摘要”
- 导出量限制：行数上限（如 50k）与时间跨度上限（可配置）
- 导出必须写审计日志：`STAT_EXPORT`

### 4.3 数据权限与脱敏（SA 与 UM 联动）

统计模块必须遵循数据范围规则：

- 医生：默认仅查看本人 + 所在科室汇总（可配置）
- 收费员/药师：可查看本岗位相关统计（如收费对账/发药量），不显示患者身份证等
- 管理员：可查看全院统计；敏感字段需要额外权限点（如 `STAT_VIEW_SENSITIVE`）

### 4.4 高级分析（可选但建议列为扩展）

原文档提到预测/异常检测/关联分析/效率分析。为保证可交付性，建议分级：

- 必做（MVP）：趋势/对比/排行/占比/导出
- 扩展（加分项）：门诊量预测、异常费用监控、流程时长分析（挂号-候诊-就诊-缴费）

每个扩展项需明确：

- 输入数据口径
- 输出结果形式
- 误差/阈值定义（如异常检测阈值）

## 5. 对外接口与对接约束（补全到“可联调”）

### 5.1 与挂号模块接口（REG → UM/SA）

- 获取患者实名信息、账号状态（是否黑名单/是否可挂号）
- 同步挂号订单与号源数据用于统计（含渠道、科室、医生、时段、状态）

### 5.2 与就诊模块接口（VISIT → SA）

- 同步就诊记录（接诊开始/结束时间）、诊断、处方状态
- 供“医生工作量”“处方量”“平均候诊时长”等统计使用

### 5.3 与收费模块接口（BILLING → SA）

- 同步支付流水、退费记录、支付方式、费用结构明细
- 供“收入汇总”“费用结构占比”“退费率”等统计使用

### 5.4 与药房模块接口（PHARM → SA）

- 同步发药记录、药品消耗、库存变动
- 供“药品消耗排行”“库存预警统计”等分析使用

### 5.5 外部系统对接预留（HIS/LIS/PACS/医保）

对接原则：

- 统一由 `integration` 适配层处理
- 对接失败要可追溯：记录请求/响应摘要、错误码、重试次数
- 对接不阻塞核心业务：可异步重试或降级（如先本地落库，后补同步）

## 7. 非功能需求（从整体项目补全与量化）

在原文档基础上，建议将非功能需求量化为可验收条款：

### 7.1 性能

- 页面响应：常规查询 ≤ 1s；大查询（含聚合）≤ 2s
- 并发：支持 ≥ 50 并发用户（课程可压测模拟）
- 导出：50k 行 Excel 导出 ≤ 10s（可配置/允许后台异步）

### 7.2 可靠性与一致性

- 关键业务（支付/退费/退号/发药）必须幂等
- 同步失败需可重试；失败记录可查询；不可出现“统计口径与业务事实长期不一致”

### 7.3 安全

- 敏感信息加密存储、脱敏展示、权限严格分级
- 关键操作留痕；审计不可篡改（追加写）

### 7.4 易用性

- 符合院内操作习惯：常用操作 ≤ 3 步完成
- 查询筛选条件可保存为“常用筛选”（可选）

### 7.5 兼容性与部署

- Windows 环境优先（课程场景）
- 打印机/扫描设备兼容（如实现打印）
- 若采用 Java Spring Boot：提供“一键运行/一键打包”说明

## 8. 验收标准（从“能用”到“可验收”）

### 8.1 功能验收（建议）

- UM：能完成账号创建/禁用/重置密码/角色授权/接口鉴权；关键操作均有审计日志
- SA：能按时间/科室/医生/渠道筛选查询；支持至少 5 个核心指标；至少 3 种图表；支持 Excel/PDF 导出并留痕

### 8.2 安全验收（建议）

- 未授权访问被拒绝；越权访问被拒绝
- 敏感字段默认脱敏；导出必须鉴权与留痕

### 8.3 性能验收（建议）

- 在预置演示数据（如 10 万挂号订单、10 万支付记录）下，关键查询仍满足响应目标（可降低规模但要写明）

## 9. 改进点总结（对应原文档的不足）

相对原 `第四组-2013112463-王颖-需求分析.docx`，本改进版重点补全：

1. **用户管理内容不足**：补全账号/登录/角色权限/数据权限/审计日志的可实现条款  
2. **统计“方法多但口径不清”**：补全指标口径、状态定义、维度与筛选规则  
3. **缺少对接描述**：补全与挂号/就诊/收费/药房模块的数据接口与同步约束  
4. **非功能难验收**：将性能/安全/可靠性条款量化为验收指标  
5. **缺少数据权限与敏感数据策略**：补全数据范围、脱敏与导出控制要求
